# Aeryx Homebrew tap

Homebrew formulas and cask for [Sock](https://joinsock.com), messaging between people and their agents.
Docs live at [joinsock.com/docs](https://joinsock.com/docs).

## What's here

| Name | Kind | What it installs |
| --- | --- | --- |
| `sock` | formula | The `sock` CLI: message your owner and conversations from scripts, jobs and agents |
| `sock-mcp` | formula | The `sock-mcp` MCP server: lets an agent message through sock as a puppet |
| `sock` | cask | Sock for Mac, the signed app (macOS 26 Tahoe or later) |

The formulas build from source with Go at the signed `vX.Y.Z` release tags of
[sock-cli](https://github.com/Aeryx-ai/sock-cli) and [sock-mcp](https://github.com/Aeryx-ai/sock-mcp).
Go is a build dependency only.

The cask installs `Sock.app` from the dmg on `https://downloads.joinsock.com`.
The app updates itself with Sparkle.

## Install

```sh
brew tap aeryx-ai/tap

brew install aeryx-ai/tap/sock            # sock CLI
brew install aeryx-ai/tap/sock-mcp        # sock MCP server
brew install --cask aeryx-ai/tap/sock     # Sock for Mac
```

The `sock` formula and the `sock` cask share a token, so `brew install aeryx-ai/tap/sock` installs the CLI.
The Mac app always needs `--cask`.

### Building from main

```sh
brew install --HEAD aeryx-ai/tap/sock
brew install --HEAD aeryx-ai/tap/sock-mcp
```

`--HEAD` builds the `main` branch of the source repo instead of the release tag.
It applies to the formulas only.

## Upgrade

```sh
brew update
brew upgrade aeryx-ai/tap/sock aeryx-ai/tap/sock-mcp
```

The cask is marked `auto_updates`, so Sparkle keeps the app current and a plain `brew upgrade` skips it.
`brew upgrade --cask --greedy aeryx-ai/tap/sock` forces Homebrew to reinstall it at the tap's version.

## Uninstall

```sh
brew uninstall aeryx-ai/tap/sock aeryx-ai/tap/sock-mcp
brew uninstall --cask aeryx-ai/tap/sock
```

`brew uninstall --cask --zap aeryx-ai/tap/sock` also deletes the app's local data:

- `~/Library/Application Scripts/ai.aeryx.sock`
- `~/Library/Application Scripts/ai.aeryx.sock.notifications`
- `~/Library/Application Scripts/group.ai.aeryx.sock`
- `~/Library/Caches/ai.aeryx.sock`
- `~/Library/Containers/ai.aeryx.sock`
- `~/Library/Containers/ai.aeryx.sock.notifications`
- `~/Library/Group Containers/group.ai.aeryx.sock`
- `~/Library/HTTPStorages/ai.aeryx.sock`
- `~/Library/Preferences/ai.aeryx.sock.plist`

## How updates land

Nobody edits `Formula/` or `Casks/` by hand. Every file there is generated by `scripts/update.sh` and says so on its first line.

- A `vX.Y.Z` tag on [sock-cli](https://github.com/Aeryx-ai/sock-cli) runs its release workflow, which runs `scripts/update.sh formula sock X.Y.Z` and pushes `Formula/sock.rb`.
- A `vX.Y.Z` tag on [sock-mcp](https://github.com/Aeryx-ai/sock-mcp) does the same for `Formula/sock-mcp.rb`.
- The Mac app's publish job writes `latest/mac.json` on `downloads.joinsock.com`, then runs `scripts/update.sh cask sock` and pushes `Casks/sock.rb`.

Each job commits as `github-actions[bot]` with a deploy key. It skips the commit when nothing changed, and rebases and retries when another release pushed first.

## Maintainers

### `scripts/update.sh`

```sh
scripts/update.sh formula sock 1.2.3       # Formula/sock.rb from sock-cli v1.2.3
scripts/update.sh formula sock-mcp 1.2.3   # Formula/sock-mcp.rb from sock-mcp v1.2.3
scripts/update.sh cask sock                # Casks/sock.rb from latest/mac.json
```

For a formula it downloads the GitHub source tarball for tag `v<version>`, hashes it and writes a Go build formula with a `main` head.
The version must be `X.Y.Z` with no `v` and no suffix; anything else is refused before any download.

For the cask it reads `latest/mac.json` and requires an `https` url, a 64 character hex `sha256` and a numeric dotted version.
The version is interpolated back into the url as `#{version}`, and livecheck reads the Sparkle appcast at `latest/mac-appcast.xml`.

It writes only the one target file and only after the tarball or manifest checks out; a failed run leaves the existing file untouched.
It does not commit or push. It needs bash 3.2 or later, `curl` and `shasum`.

Environment overrides, used by the tests to serve fixtures over `file://`:

| Variable | Default |
| --- | --- |
| `DOWNLOADS_URL` | `https://downloads.joinsock.com` |
| `GITHUB_ARCHIVE_URL` | `https://github.com/Aeryx-ai` |

The generated formula `url` and `head` lines always point at GitHub; only the download source moves.

### Checks

`make check` runs everything CI runs:

- `make build` parses every formula and cask with `ruby -c`
- `make test` runs `tests/update_test.sh` against fake manifests and tag tarballs
- `make lint` runs `shellcheck` on the scripts and `brew style` on the formulas and cask

It needs Homebrew, Ruby and `shellcheck`.
CI ([`.github/workflows/ci.yml`](.github/workflows/ci.yml)) runs `make check` on macOS for every push to `main` and every pull request.
