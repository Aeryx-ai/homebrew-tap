# Contributing

This is the Homebrew tap for Sock: `Formula/sock.rb` ([sock-cli](https://github.com/Aeryx-ai/sock-cli)), `Formula/sock-mcp.rb` ([sock-mcp](https://github.com/Aeryx-ai/sock-mcp)) and `Casks/sock.rb` (Sock for Mac). All three are generated by `scripts/update.sh`.

## Before you start

- Open an issue before anything beyond a small fix (a typo, a doc correction, an obvious bug in `scripts/update.sh`).
- A bug in `sock` or `sock-mcp` itself belongs in that repo, not here.
- Report vulnerabilities privately, never in an issue, pull request or discussion. Use the private vulnerability reporting of the affected project as its SECURITY.md describes: [sock-cli](https://github.com/Aeryx-ai/sock-cli/security/advisories/new) for `sock` and for this tap's scripts, [sock-mcp](https://github.com/Aeryx-ai/sock-mcp/security/advisories/new) for `sock-mcp`.

## Dev setup

You need macOS with:

- Homebrew, for `brew style`, `brew audit` and installing formulas.
- Ruby, for `ruby -c`. macOS ships one; Homebrew's works too.
- shellcheck: `brew install shellcheck`. CI installs the current Homebrew version the same way.
- bash, curl and shasum. `scripts/update.sh` must run on macOS `/bin/bash` 3.2: no associative arrays and no other bash 4 features.

CI runs `make check` on `macos-latest`.

| Target | Does |
|---|---|
| `make build` | Parses every `Formula/*.rb` and `Casks/*.rb` with `ruby -c` |
| `make test` | Runs `tests/update_test.sh` |
| `make lint` | `shellcheck` on `scripts/update.sh` and `tests/update_test.sh`, `brew style` on every formula and cask |
| `make check` | `build`, `test`, `lint` |

`make install` and `make redeploy` print a note: a tap is installed with `brew tap aeryx-ai/tap`.

## Never edit Formula/ or Casks/ by hand

Every file in `Formula/` and `Casks/` starts with `Generated by scripts/update.sh ... Do not edit.` and is overwritten on the next release. To change a formula or the cask, change the template in `scripts/update.sh` and regenerate:

```sh
scripts/update.sh formula sock 0.3.0       # Formula/sock.rb from the sock-cli v0.3.0 tag
scripts/update.sh formula sock-mcp 0.5.0   # Formula/sock-mcp.rb from the sock-mcp v0.5.0 tag
scripts/update.sh cask sock                # Casks/sock.rb from https://downloads.joinsock.com/latest/mac.json
```

A formula is built from the GitHub source tarball of the signed `v<version>` tag; the script downloads it and records its sha256. The cask points at the dmg named by the live mac manifest. The script writes the one file only when its tarball or manifest is present and well formed.

## Working across repos

The formulas follow the sock-cli and sock-mcp release tags. Their release workflows run `scripts/update.sh` from this repo and push the result, so a new upstream tag needs no PR here. To try a formula against unreleased upstream code, build `main`:

```sh
brew install --HEAD aeryx-ai/tap/sock
```

A change to a formula's `test do` block must match what the binary prints: `sock --version` prints the version and `sock-mcp --help` mentions `outbound-only` and exits 1.

## Making a change

1. Fork, then branch from `main`.
2. Change `scripts/update.sh`. Add a case to `tests/update_test.sh` for it. A bug fix starts with a case that fails without the fix. The tests serve fake manifests and tag tarballs over `file://` through `DOWNLOADS_URL` and `GITHUB_ARCHIVE_URL`, so they need no network.
3. Regenerate the affected files with `scripts/update.sh` at the current release versions and commit them with the script change.
4. Test the formula locally (below).
5. Run `make check`. It must pass. CI runs the same target.
6. Keep a PR to one change.

## Testing a formula locally

Homebrew refuses to install from a file path unless `HOMEBREW_DEVELOPER` is set:

```sh
HOMEBREW_DEVELOPER=1 brew install --build-from-source ./Formula/sock.rb
brew test sock
brew style Formula/sock.rb
```

`brew audit` works on tapped names, so audit from a tap. Tap this repo, then work in the tapped clone with your fork as a remote:

```sh
brew tap aeryx-ai/tap
cd "$(brew --repository aeryx-ai/tap)"
brew install --build-from-source aeryx-ai/tap/sock
brew test aeryx-ai/tap/sock
brew audit --strict --online aeryx-ai/tap/sock
brew audit --strict --online --cask aeryx-ai/tap/sock
brew style aeryx-ai/tap
```

Replace `sock` with `sock-mcp` for the MCP formula. Uninstall with `brew uninstall sock` when done.

## Commit messages

- Imperative subject, short (about 50 characters, 72 at most), no trailing period: `Pin the cask livecheck to the short version`.
- A body that explains why, not what the diff already shows.
- One logical change per commit.
- Signed commits are encouraged: `git commit -S` or `git config commit.gpgsign true`. GPG and SSH keys both work.
- Release workflows commit formula updates as `Update sock to X.Y.Z`; leave that subject to them.

## Pull requests

- Link the issue it resolves.
- Say what changed and why, and which of `brew install`, `brew test`, `brew audit` and `brew style` you ran.
- Include the `scripts/update.sh` change, its test and the regenerated files.
- CI must be green before review. A maintainer reviews every PR. Push review fixes as new commits; the maintainer may squash on merge.

## Releases (maintainers)

The tap has no tags and no release workflow of its own. Releases happen upstream: a signed annotated `vX.Y.Z` tag on sock-cli or sock-mcp runs that repo's `release.yml`, whose `tap` job runs `scripts/update.sh formula <name> <version>` here and pushes `Update <name> to <version>` to `main`. Pushes retry with a rebase when both release at once. The cask is regenerated with `scripts/update.sh cask sock` once a new Mac build is live in the manifest.
